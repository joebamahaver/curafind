# Medical MCP research flow

The browser calls `searchMedicalResearch` and `answerMedicalQuestions` in `src/app/actions/medical-research.ts`. Both delegate to `src/lib/medical-research.ts`; they do not make requests to the app's own API. `/api/research` exposes the same functions for curl and other clients.

Each search creates a fresh [Strands SDK](https://github.com/strands-agents/harness-sdk) `Agent` with `GoogleModel` using `goog3` (`gemini-3.1-flash-lite`). It connects to Medical MCP over Streamable HTTP, searches the selected sources, and can call the app's `ask_eligibility_questions` tool. That tool uses Strands interrupts to pause for user input. A session snapshot preserves the research conversation until answers arrive, without sharing memory between searches.

The system prompt is in `src/lib/medical-system-prompt.ts`. Final output validates citations against retrieved source records. Original abstracts and trial summaries are inserted from those records, rather than regenerated by the model. Missing facts remain uncertain; no generated efficacy percentages are presented.

`src/lib/medical-model-context.ts` reduces the evidence sent to the model. Trials retain IDs, titles, URLs, complete eligibility fields, complete brief summaries, conditions, treatment names, key design fields and sites with known coordinates inside the travel radius. Eligibility is an ordered list of entries with an ID, original field name and original text; multiline criteria retain every line. The question tool references those IDs, and the server supplies original criterion text and source IDs to the browser. This avoids model-generated copies and repeated validation failures from paraphrasing. Counts expose omitted distant sites and sites whose distance is unknown. Administrative metadata, contacts, detailed descriptions and unrelated protocol sections stay in raw `sources`. Article details retain the complete abstract and provenance, while attached article bodies are omitted. Other text summaries are preserved without transport metadata or duplicate structured payloads.

Identical successful tool requests reuse the original source ID and return a short pointer to earlier evidence, avoiding another MCP request and another copy in model history. Terminal logs show `raw` and `model` character counts per retrieval and estimated input tokens per model turn. Character counts measure payload size, not exact token counts. Search result limits and model choice are unchanged. Start a new search after updating the app; earlier in-memory snapshots can still contain the old full responses.

## Gemini resume and cleanup

Strands forces `strands_structured_output` when Gemini finishes with plain text. Gemini's forced function-calling mode rejects the report's nested `maxItems` constraints with a generic 400, even though the same schema works in automatic mode. The model-facing report schema describes the limits instead; the hydrated report is still strictly validated against `medicalReportSchema` (25 trials, 20 articles, source checks and all other validations).

Cleanup errors are caught separately so an MCP disconnect abort cannot replace a model error or successful result. Next.js development's HMR fetch cache is disabled because it clones and retains live MCP response streams, including uncached fetches. Restart the dev server after changing `next.config.ts`; production caching is unaffected by this development setting.

To check the forced-output path against the real provider, run `npm run test:mcp -- --agent --debug --force-final`. This supplies unknown (`null`) answers, simulates one plain-text completion, and verifies that Strands can force the final output tool. Use `--condition="Alcohol Addiction"` to change the synthetic test condition.

## Container and eligibility extension

The Dockerfile pins Medical MCP source at commit `9e98f2eb10a6830730ff8fc2228bb54f9f75c154`. Its upstream trial tool returns summaries without eligibility criteria, so the container adds `search-trials-with-eligibility`. This tool resolves the U.S. ZIP code, applies a geographic radius and recruiting/upcoming filter to ClinicalTrials.gov, and returns full protocol JSON. The app overrides location and result limits with validated user/config values.

`registerTrialSearch(server)` must run **inside `createMedicalMcpServer()`, before `return server`**. There is no global `server`; registering at module scope causes the reported `ReferenceError`. The build patch in `docker/medical-mcp/extend.mjs` inserts it inside the factory, so every HTTP MCP session receives the tool.

```sh
docker compose up --build -d medical-mcp
docker compose logs --tail=50 medical-mcp
npm run test:mcp
```

An existing server can be used with `MEDICAL_MCP_URL`, but it must expose the same eligibility extension plus `search-medical-literature` and `get-article-details`. A plain upstream installation is insufficient for the eligibility questions. The app checks these tools at connection time.

## Configuration

All settings are server-only and shown in `.env.example`.

| Variable | Default | Purpose |
| --- | --- | --- |
| `GEMINI_API_KEY` | Required | Google inference credentials |
| `MEDICAL_MCP_URL` | `http://127.0.0.1:3100/mcp` | MCP transport URL |
| `MEDICAL_TRIAL_LIMIT` | 10 | Trials retrieved per search, maximum 25 |
| `MEDICAL_RESEARCH_LIMIT` | 5 | Articles retrieved per search, maximum 20 |
| `MEDICAL_MAX_TURNS` | 20 | Agent turn budget, maximum 50 |
| `MEDICAL_TIMEOUT_SECONDS` | 180 | Each initial/resume invocation, maximum 600 |
| `NCBI_API_KEY` | Optional | Passed to the container for PubMed requests |

For a small live test, set trial limit to 2 and research limit to 1. Source calls have a 30-second timeout. The overall timeout applies to agent invocation; MCP connection setup is separate.

## Test the HTTP interface

With the app and MCP container running:

```sh
curl --max-time 240 -sS http://localhost:3000/api/research \
  -H 'Content-Type: application/json' \
  -d '{"condition":"asthma","zipCode":"64108","travelDistanceMiles":100,"clinicalTrials":true,"offLabelDrugsOrSupplements":true}'
```

If the response has `status: "questions"`, take its `sessionId` and question IDs. Send answers with the same endpoint; use a number, boolean or string matching each question's `type`. `null` or an omitted answer means unknown.

```sh
curl --max-time 240 -sS http://localhost:3000/api/research \
  -H 'Content-Type: application/json' \
  -d '{"sessionId":"REPLACE_WITH_SESSION_UUID","answers":[{"id":"REPLACE_WITH_QUESTION_ID","answer":42}]}'
```

The agent can ask a further question batch or return `status: "complete"` with `report: { summary, trials, research, limitations }`. Failed calls return an `error`; malformed JSON/schema inputs return 400 and research failures return 502.

## Intercept JSON

Pass `onResults` to `ResearchRequest` to intercept each question/completion packet:

```tsx
<ResearchRequest onResults={async (result, request, signal) => {
  console.log(result.sources); // Original MCP tool inputs and responses.
  if (result.status === "complete") {
    console.log(result.report.trials, result.report.research);
    // Process or persist this object here. Respect signal.aborted for stale searches.
  }
}} />
```

On the server, import `startMedicalResearch` or `resumeMedicalResearch` directly. `sources` always retains raw MCP response objects alongside tool names, inputs and source IDs. The browser also has a “View results JSON” disclosure.

## Runtime limits

Pending snapshots are held in memory for 30 minutes, with at most 50 pending sessions. A process restart loses them. Deployments with multiple workers need a shared snapshot store and atomic locking, or sticky routing, before users can reliably resume on another worker. Results and patient answers are not persisted to disk.

Editing/unmounting the form suppresses stale browser updates. Next.js Server Function requests already in flight continue on the server until completion or timeout. The HTTP route also passes the request abort signal to the agent. Inference and upstream availability can still vary; the live smoke test verifies integration, not every condition or patient's eligibility.
